# ATP 1.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship agent-trust-plane 1.0.0. It is the proof release: a published, reproducible benchmark against competitors; incident cases; a red-team harness; and a frozen, versioned set of formats with a compatibility promise.

**Architecture:** There are two tracks on one branch.
- **Core track (Phases B and C):** fixes and the breaking format changes from the unmerged `v0.4-file-format-versions` plan, all landing before the freeze. The changes go into `packages/`, `services/gateway` and `adapters/mcp`.
- **Bench track (Phases A, D, E, F and G):** it extends the separate `bench/` uv project built in the previous plan.
- **Phase H:** freezes the formats, writes the results page and prepares the release. Publishing is owner-gated.

**Tech Stack:** Python 3.12 / 3.13, uv workspace, pydantic v2, FastAPI, the `mcp` SDK, `cryptography` (Ed25519), pytest, GitHub Actions. Bench: `agentdojo==0.1.35`, agentgateway v1.6.0 and ToolHive v0.55.2 (Linux binaries, WSL lane), Claude Code (`claude -p`) and Codex CLI (`codex exec`) on the owner's subscriptions.

**Spec:** `docs/superpowers/specs/2026-11-03-atp-1x-design.md`. It supersedes P2–P7 of `docs/superpowers/plans/2026-11-03-atp-1x-index.md` and continues `docs/superpowers/plans/2026-11-03-atp-bench-replay.md`, whose ledger is `.superpowers/sdd/2026-11-03-atp-bench-replay/progress.md`. The format items come from `docs/release/v1.0.0-plan.md` on branch `v0.4-file-format-versions`; read it with `git show v0.4-file-format-versions:docs/release/v1.0.0-plan.md`.

## Global Constraints

- **$0 spend.** No paid APIs, hosting or audits. The live-agent track uses only the owner's existing Claude Code and Codex subscriptions.
- **Branch:** `release/v1/B12-atp-1.0`, created from `release/v1/B11-bench-replay` at `d88d20c`. No force pushes.
- **Owner gates:**
  - Merges, pushes, tags (including `bench-annotations-v1` and `v1.0.0`) and PyPI publishing need explicit owner approval.
  - Every owner-gated step is marked **[OWNER GATE]**. Execution stops there and asks.
- **Status vocabulary:** PASS / FAIL / SKIP / NOT_APPLICABLE / INCONCLUSIVE / NOT_MEASURED / ENV_BLOCKED. A layer or tool that cannot run here is ENV_BLOCKED, with the error text, never estimated.
- **Public naming:** copy says "the agent authorization platform". The package, CLI and URLs stay `agent-trust-plane` / `atp`.
- **Delegation sources:** delegations may use the user prompt and the pre-injection environment only, never the injection text or the task's ground-truth calls. `bench/annotations/` is frozen once tagged `bench-annotations-v1`; the runner enforces this.
- **Competitor fairness:** each competitor policy is generated per task from the same annotation, as strongly as that product allows. Anything dropped is listed with the competitor's doc URL (ruling R13).
- **Honest claims:** the README keeps "not independently audited" and "no users yet" until each stops being true. The owner's red team is never called independent.
- **Python floor and CI:** Python ≥ 3.12. CI stays green on ubuntu 3.12/3.13, windows 3.13, and the macos leg added in Task C9. Tests are never suppressed. Counts are read from `--junitxml`, because the pytest config hides the summary.
- **Breaking changes:** all of them land in Phase C. After Task H1 (freeze), any change to a frozen surface fails `tests/compat/`.
- **Windows root venv:** `.venv/Scripts/atp.exe` may be locked by a running preview, so use `uv run --no-sync` at the repo root and never `uv sync` there while it is locked.

## Review Focus

1. **Upgrade from a real 0.3.2 home.** Files: `.atp/` with an HMAC `keys.env`, an unversioned `atp-mcp.yaml` and `policies.yaml`. Expected: `atp` still starts, warns once per file, `atp migrate` makes the files current, and old traces still verify. (Test in Task C10.)
2. **Key rotation mid-flight.** A grant minted under the old `kid` still verifies until it expires after `atp keygen --rotate`, and a grant with an unknown `kid` is GRANT_SIGNATURE_INVALID. (Test in Task C2.)
3. **Budget leakage and races.** A reservation whose execution never reports back is released at grant expiry. Two concurrent reservations cannot together exceed the budget. (Tests in Task C4.)
4. **Approval misuse.** An approval for action hash A cannot authorize a modified action B. An expired approval, or an approver without the role, denies. Replaying one approval twice issues one grant. (Tests in Task C3.)
5. **A competitor binary missing, the wrong platform, or failing to start.** The layer reports ENV_BLOCKED with the error and the run continues. It never becomes DENIED, ALLOWED or a crash. (Tests in Task D1.)

### Task C2: Ed25519 execution grants with `kid`

**Files:**
- `services/gateway/src/atp_gateway/grants.py`
- `settings.py` and `wiring.py` in `services/gateway/src/atp_gateway/`
- `packages/cli/src/atp_cli/home.py`
- `services/gateway/src/atp_gateway/__main__.py` (keygen)
- `packages/core/src/atp_core/ids.py` (reuse `new_secret_key` only for operator keys)
- the gateway's `pyproject.toml` (declare `cryptography>=50`)
- tests

**Interfaces:**
- **Token:** `TOKEN_VERSION = "atp-grant/2"`. Format `b64(header).b64(claims).b64(sig)`, where `header = {"alg": "EdDSA", "kid": <kid>, "v": "atp-grant/2"}` and the signature covers `b64(header) + "." + b64(claims)`. `atp-grant/1` HMAC tokens are rejected with GRANT_MALFORMED. Grants are single-use and short-lived, so no compatibility window is needed.
- **Signer and verifier:**
  - `GrantSigner(private_key: Ed25519PrivateKey, kid: str)`, with `.mint(claims) -> str` and `.kid`
  - `GrantVerifier(public_keys: Mapping[str, Ed25519PublicKey])`, with `.verify(token) -> GrantClaims`
  - `kid = sha256(raw_public_key).hexdigest()[:16]`
- **Key storage:**
  - `.atp/keys/grant-<kid>.key` holds the PKCS8 PEM, mode 0600 where the OS allows.
  - `.atp/keys/grant-<kid>.pub` holds the public key.
  - `keys.env` keeps `ATP_GRANT_SIGNING_KID=<kid>`. The old `ATP_GRANT_SIGNING_KEY` is accepted once, so `ensure()` migrates by generating an Ed25519 key, then removes it.
- **Rotation:** `atp keygen --rotate` creates a new active key and keeps old public keys for verification for one `grant_ttl`.

  - `test_mint_verify_roundtrip`
  - `test_tampered_claims_rejected`
  - `test_unknown_kid_is_signature_invalid`
  - `test_v1_hmac_token_rejected`
  - `test_old_kid_verifies_after_rotation` (Review Focus 2)
  - `test_home_migrates_hmac_key`
  - `test_private_key_never_in_upstream_env` (extend `shared_upstream_warning` and the leak check to `ATP_GRANT_SIGNING_KID` and the key paths)

**Files:**

**Interfaces:**
- **Model:** `Budget(amount: Money, period: Literal["day", "week", "month"])`, with periods anchored to UTC calendar boundaries.
- **Chain resolution:** the tightest budget wins. If the periods differ, each budget applies independently.
- **Store:**

- **Decision:** a decision whose amount plus the reserved and settled spend in the period exceeds the budget is DENY with `PAYMENT_EXCEEDS_BUDGET`. The explain output shows `limit`, `spent`, `reserved` and `requested`.
