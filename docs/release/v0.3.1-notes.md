# Agent Trust Plane v0.3.1

Patch release following the first public CI run. No new features.

## What changed

- `atp demo wrap --out <relative path>` no longer resolves the output
  directory twice (the demo's own `atp` subprocesses run from that
  directory). Found by the first GitHub Actions run on ubuntu and windows.
- A regression test for that shape (`test_demo_wrap_accepts_a_relative_out_dir`).
- Compatibility matrix and verification record now reflect the remote CI
  results instead of "not run on a remote".

## Verified

GitHub Actions on `main` after the fix
(https://github.com/TimelessVisions/agent-trust-plane/actions/runs/35234834560
and the following docs commit):

- ubuntu-latest, Python 3.12 — PASS
- ubuntu-latest, Python 3.13 — PASS
- windows-latest, Python 3.13 — PASS
- `package` (wheel build, isolated `uvx` run, pip-audit, SBOM) — PASS
- `dashboard` (typecheck, production build) — PASS

Locally (Windows 11, Python 3.14): the full release checklist in
`docs/release/verification.md`, plus the previously failing invocation
`atp demo wrap --out <relative dir>` from a clean temporary directory.

## Known limitations

- macOS is not verified (not in the CI matrix).
- No IDE MCP client (Claude Desktop, Cursor, VS Code, Claude Code) has been
  tested; the compatibility matrix lists them as not verified.
- Not published to PyPI; install from the repository or a built wheel.
- Only the mediated path is protected: an agent that can reach a tool
  without the proxy is not stopped (`docs/security/enforcing-the-boundary.md`).
- Agent credentials are bearer tokens with expiry and revocation, no proof
  of possession; the operator key and `.atp/keys.env` are omnipotent.
- Single-use grants prove one release, not exactly-once external effects.
- Not independently security audited. Not production software.

Full lists: `docs/security/threat-model.md`, `docs/security/security-review.md`.
